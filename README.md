# Sparse Sensor Placement in Multi-Agent Reinforcement Learning Control of Rayleigh-Bénard Convection

This repository contains the code accompanying the paper **"Sparse Sensor Placement in Multi-Agent Reinforcement Learning Control of Rayleigh-Bénard Convection"**. It reproduces the experiments of the paper: multi-agent reinforcement learning (MAT and parameter-sharing IPPO) for Rayleigh-Bénard convection, dense MAT experts, expert-apprentice distillation with grouped sparsification, and the resulting sparse sensor sets.

The README walks through the experiments in the order in which they depend on each other. For every experiment it lists the launch command, the analysis command, and where the resulting figures and tables are written.

## Contents

| Path | Content |
|---|---|
| `RL/` | Snapshot of the custom Julia `RL` package (commit `b48263c`) that was used for all experiments. It is based on an early version of [ReinforcementLearning.jl](https://github.com/JuliaReinforcementLearning/ReinforcementLearning.jl), but has been heavily customized (e.g. MAT and parameter-sharing PPO agents for multi-agent control). |
| `RBmodel300.jld2`, `RBmodel300_chebychev.jld2` | Fixed initial condition (Ra = 1e4). |
| `Run_Files/` | Environment, MAT/IPPO agent and training loop for every setting. All experiments include these files. |
| `VaryingIC_Corpus/` | Initial-condition corpora (train/validation/test basis states) for Ra = 1e4, 5e4 and 1e5. |
| `Expert_Apprentice_Distillation/` | Distillation corpus generation, apprentice training, Pareto archive, and the trained dense MAT experts in `experts/`. |
| `Baselines/` | Expert and unactuated reference rollouts on the test cases, including their results. |
| `<study>/` | One directory per experiment, described below. |

Shipped artifacts are limited to small files that are needed as inputs:

- the initial-condition corpora,
- the dense MAT experts (`Expert_Apprentice_Distillation/experts/`, `Higher_Ra_Study/experts/`),
- the expert and unactuated baselines (`Baselines/results/`, `Higher_Ra_Study/Baselines/`),
- `paper_snapshot/` directories in `GO_Sensitivity`, `FixedIC_Ra1e4_Sparsity` and `VaryingIC_Ra1e4_Sparsity`. They contain only the frozen apprentice selections (`C_match`, selected sparse candidates and their model checkpoints) that the sensor-noise study and the masked-training study use as inputs.

Everything else, including the distillation corpus (several GB), is generated by the commands below and written to `results/` (or `worker_results/`) inside the respective study directory.

## Setup

Install Julia 1.12 and instantiate the project from the repository root:

```bash
julia setup.jl
```

`Project.toml` resolves `RL` from the local `RL/` directory. The `[compat]` sections of `Project.toml` and `RL/Project.toml` start at the package versions that were used for the paper. All simulations and trainings run on the CPU.

All commands below are executed from the repository root. Scripts are started with:

```bash
julia --startup-file=no --project=. <script>.jl
```

The experiments are long-running. Each experiment therefore comes with a `launch_tmux.sh` launcher that starts every worker in its own detached, self-closing `tmux` session (Linux with `bash` and `tmux`). The launchers have these properties:

- `--preview` prints the planned sessions without starting anything.
- Completed work is skipped when a launcher is called again, so an interrupted launch is resumed by repeating the command.
- `JULIA_BIN` selects the Julia executable. `--openblas-threads` and `--omp-threads` control the threads per worker.
- Launch logs are written to `results/.../launches/` of the respective study.

## Reproduction workflow

The order below follows the dependencies between the experiments. Steps 1–3 cover the reinforcement-learning experiments and produce the dense MAT experts. The experts are shipped, so the distillation experiments (steps 4–10) can start directly with step 4. The higher-Rayleigh-number study (step 11) is independent of steps 1–10.

### 1. MAT architecture stability — `MAT_Stability`

This step compares three MAT variants (`python_like`, `modified_half`, `modified_full`) with five paired replicates under fixed and varying initial conditions (30 workers, 2,000/4,000 episodes).

```bash
bash MAT_Stability/launch_tmux.sh            # optional: --protocol fixed|varying
julia --startup-file=no --project=. MAT_Stability/collect_results.jl
```

Artifacts are written to `MAT_Stability/results/collected/`: the learning-curve and final-performance figures (SVG/PDF), `metrics.csv` and `summary.jld2`.

### 2. MAT versus IPPO — `MAT_IPPO_Comparison`

This step compares MAT (`modified_full`) and parameter-sharing IPPO over ten seed pairs per setting. Five seed pairs are newly generated from the fixed master seed of the paper. The other five reuse the `modified_full` runs of step 1.

The first launch can start while step 1 is running:

```bash
bash MAT_IPPO_Comparison/launch_tmux.sh --n-runs 5 --look-for-imports false --max-workers 20
```

After step 1 has finished, import its runs and train their IPPO partners:

```bash
julia --startup-file=no --project=. MAT_IPPO_Comparison/import_mat_stability.jl --n-runs 5
bash MAT_IPPO_Comparison/launch_tmux.sh --n-runs 5 --look-for-imports true --max-workers 20
```

Then collect the results:

```bash
julia --startup-file=no --project=. MAT_IPPO_Comparison/collect_results.jl
```

Artifacts:

- `MAT_IPPO_Comparison/results/analysis/plots/` holds the combined learning-curve, validation and paired final-100 figures.
- `MAT_IPPO_Comparison/results/analysis/` holds the CSV summaries, including the validation ranking of the MAT expert candidates.

### 3. Dense MAT experts — `MAT_expert_training` (optional)

This step continues the validation-ranked MAT runs of step 2 until the expert criterion is met, then publishes the experts to `Expert_Apprentice_Distillation/experts/`. The experts used in the paper are already shipped there, so this step is only required to retrain them. Retraining follows the same procedure, but it is not guaranteed to give bit-identical networks.

```bash
bash MAT_expert_training/launch_tmux.sh
```

If no run reaches the criterion, `finalize_best_so_far.jl --protocol all` freezes the best checkpoints so far. Test-set scores and reward curves of the selected experts are written to `MAT_expert_training/results/test/`.

### 4. Distillation corpus — `Expert_Apprentice_Distillation`

This step rolls out the dense experts deterministically and stores their observations and actions. It is required by steps 6–10.

```bash
bash Expert_Apprentice_Distillation/launch_tmux.sh --protocol fixed
bash Expert_Apprentice_Distillation/launch_tmux.sh --protocol varying --split train
bash Expert_Apprentice_Distillation/launch_tmux.sh --protocol varying --split validation --max-workers 2
bash Expert_Apprentice_Distillation/launch_tmux.sh --protocol varying --split test --max-workers 4
```

- **Fixed:** one worker, written to `worker_results/fixed/`.
- **Varying:** 40 training, 2 validation and 4 test workers, written to `worker_results/varying/<split>/`. The varying training set is about 3.3 GiB.
- **Determinism:** the corpus contains no randomness. With the shipped experts and initial-condition corpus it is regenerated up to floating-point effects of the BLAS library (see [Reproducibility](#reproducibility)).

### 5. Expert and unactuated baselines — `Baselines` (optional)

These are the reference rollouts of the dense experts and of zero actuation on the test cases (1 fixed, 8 varying). Their results are shipped in `Baselines/results/` and are used by the paper tables of steps 6–9. To regenerate them:

```bash
bash Baselines/launch_tmux.sh
```

### 6. GO sensitivity study — `GO_Sensitivity`

This study measures the sensitivity of Group Ordered (GO) regularization to its strength (separate-channel grouping, five strengths × three replicates, plus GR as reference) under fixed and varying initial conditions. Its analysis freezes the candidates `C_match` and `C_sparse`.

```bash
bash GO_Sensitivity/launch_study_tmux.sh      # 36 training + 2 analysis sessions
julia --startup-file=no --project=. GO_Sensitivity/make_paper_figures.jl
```

The analysis sessions start automatically and run the terminal test rollouts of the frozen candidates.

Artifacts:

- `GO_Sensitivity/results/study/<fixed|varying>/analysis/` holds the per-setting analysis.
- `GO_Sensitivity/results/study/paper/` holds the paper figures (SVG/PDF), `table_1_summary.csv/.md` and `paper_metrics.md`.

### 7. Fixed-IC sparse sensor placement — `FixedIC_Ra1e4_Sparsity`

This study compares GO, GR, Group Lasso and GrOWL, each with grouped (GC) and separate (SC) channels, under fixed initial conditions. It produces Pareto sets of active inputs versus validation matching, frozen candidate selection, and closed-loop tests.

```bash
bash FixedIC_Ra1e4_Sparsity/launch_tmux.sh                  # 72 training + 8 analysis sessions
julia --startup-file=no --project=. FixedIC_Ra1e4_Sparsity/make_paper_figures.jl --experiment-id <ID>
```

Each launch creates an experiment ID (`YYMMDD_HHMMSS`), which the launcher prints. Without `--experiment-id`, the figure script uses the newest experiment.

Artifacts:

- `FixedIC_Ra1e4_Sparsity/results/<ID>/<configuration>/analysis/` holds the Pareto fronts, selected candidates and test results.
- `FixedIC_Ra1e4_Sparsity/results/<ID>/paper/` holds the sensor-mask and Pareto figures and `table_1_selected_candidates.csv/.md`.

### 8. Varying-IC sparse sensor placement — `VaryingIC_Ra1e4_Sparsity`

This is the same study as step 7 under varying initial conditions.

```bash
bash VaryingIC_Ra1e4_Sparsity/launch_tmux.sh
julia --startup-file=no --project=. VaryingIC_Ra1e4_Sparsity/make_paper_figures.jl --experiment-id <ID>
```

Artifacts are written to `VaryingIC_Ra1e4_Sparsity/results/<ID>/paper/`. They include `figure_2_varying_sc_pareto`, the four-panel comparison of the SC methods.

PDF exports from PlotlyJS contain an empty second page, which can be dropped.

### 9. Dense parameter-sharing apprentice — `Simple_NNA_Study`

This repeats step 8 with a dense IPPO-like apprentice instead of the MAT apprentice (GO/GR × GC/SC). Each configuration is launched separately with one shared experiment ID:

```bash
EXPERIMENT_ID="simple_nna_$(date -u +%y%m%d_%H%M%S)"
for config in go-gc go-sc gr-gc gr-sc; do
    bash Simple_NNA_Study/launch_tmux.sh --experiment-id "$EXPERIMENT_ID" --config "$config"
done
julia --startup-file=no --project=. Simple_NNA_Study/make_paper_figures.jl --experiment-id "$EXPERIMENT_ID"
```

Artifacts are written to `Simple_NNA_Study/results/<ID>/paper/`: the sensor-mask, channel-pruning and Pareto figures, and the candidate table.

### 10. Sensor noise and masked RL training

These two experiments use the frozen apprentice selections of steps 6–8. By default they read the selections of the paper from the shipped `paper_snapshot/` directories, so they do not require steps 6–8 to be rerun. To use your own selections instead, pass:

```text
--fixed-sparsity-results FixedIC_Ra1e4_Sparsity/results/<ID>
--varying-sparsity-results VaryingIC_Ra1e4_Sparsity/results/<ID>
--go-study-results GO_Sensitivity/results/study    # noise study only
```

**Sensor noise — `Noise_Study`.** This compares the dense expert, the sparsest SC apprentice and `C_match` under Gaussian sensor noise at ten levels. It requires the distillation corpus of step 4, which is used to compute the channel scales.

```bash
bash Noise_Study/launch_tmux.sh                # 60 sessions
julia --startup-file=no --project=. Noise_Study/make_paper_figures.jl
```

Artifacts are written to `Noise_Study/results/<ID>/paper/`: the noise-robustness figure, the `C_match` mask figure and `table_1_noise_robustness.csv/.md`.

**Direct RL training on selected sensors — `MaskedTraining`.** This trains MAT with the frozen GC and SC sensor masks of steps 7 and 8. It reuses the seed pairs and initial-condition sequences of step 2, and compares against its dense MAT runs. It therefore requires the results of step 2.

```bash
bash MaskedTraining/launch_tmux.sh             # 40 sessions
julia --startup-file=no --project=. MaskedTraining/make_paper_figures.jl
```

Artifacts are written to `MaskedTraining/results/paper/`: the combined learning-curve figure and `final_100_statistics.csv`.

### 11. Higher Rayleigh numbers — `Higher_Ra_Study`

This repeats the expert → corpus → GO/GR pipeline at Ra = 5e4 and Ra = 1e5. The experts and baselines are shipped in `Higher_Ra_Study/experts/` and `Higher_Ra_Study/Baselines/`.

To retrain the experts (optional), first train MAT at both Rayleigh numbers:

```bash
bash MAT_expert_training/launch_tmux_ra5e4.sh --runs 10 --episodes 4000
bash MAT_expert_training/launch_tmux_ra1e5.sh --runs 10 --episodes 4000
```

Then select the experts, plot the learning curves and evaluate the experts and unactuated baselines on the test cases:

```bash
julia --startup-file=no --project=. Higher_Ra_Study/analyze_runs.jl
julia --startup-file=no --project=. Higher_Ra_Study/compute_unactuated_baselines.jl
```

Generate the distillation corpora (for each of `ra5e4` and `ra1e5`):

```bash
bash Higher_Ra_Study/launch_tmux_ra5e4.sh --split train
bash Higher_Ra_Study/launch_tmux_ra5e4.sh --split validation --max-workers 2
bash Higher_Ra_Study/launch_tmux_ra5e4.sh --split test --max-workers 4
```

Run the GO/GR study (60 training + 4 analysis sessions per Rayleigh number) and create the paper figures:

```bash
bash Higher_Ra_Study/GO_GR_Study/launch_tmux_ra5e4.sh --experiment-id <ID>
bash Higher_Ra_Study/GO_GR_Study/launch_tmux_ra1e5.sh --experiment-id <ID>
julia --startup-file=no --project=. Higher_Ra_Study/GO_GR_Study/make_paper_figures.jl --experiment-id <ID>
```

Artifacts are written to `Higher_Ra_Study/GO_GR_Study/results/<ra>/<ID>/paper/`: the Pareto and sensor-mask figures and the candidate tables per Rayleigh number.

## Reproducibility

- All randomness is seeded. The seed plans are fixed in the code; MAT/IPPO run seeds are derived from them.
- The `RL/` snapshot is the version used for the paper, and the compat bounds start at the package versions used for the paper.
- Multi-threaded OpenBLAS can change floating-point summation order between runs, which leads to differences of about 1e-7 in closed-loop rollouts. With `--openblas-threads 1` (or `OPENBLAS_NUM_THREADS=1`), deterministic rollouts are bit-identical between runs. For example, the shipped Fixed-IC expert baseline is reproduced exactly with this setting.
- Reinforcement-learning trainings over thousands of episodes react sensitively to floating-point differences between machines and library builds. Retrained agents are therefore statistically equivalent to the published ones, but not necessarily bit-identical. This is why the experts are shipped.
- Selections of apprentice candidates use validation data only. Test cases are evaluated after the selection has been frozen.
